# Concept Atlas

## Core Concepts

| Concept | Short Definition | Connected Concepts | Status |
| --- | --- | --- | --- |
| 仪器感 | 界面像一台可操作、可读数、可校准的工具，而不是一篇说明文。 | 控制、读数、反馈、容错 | developing |
| 可供性 | 用户不读说明也能感到某物可以被拖动、点击、比较或调整。 | affordance、视觉暗示、指针行为 | developing |
| 映射 | 控制动作和结果之间的可理解关系。 | 竖向金额轴、价格增长、空间方向 | developing |
| 反馈 | 用户动作之后系统立即回应，让用户知道状态改变。 | 当前金额、焦点项、同价位对照 | developing |
| 约束 | 用空间、状态和规则减少错误操作。 | 模式切换、标签泳道、按钮作用域 | developing |
| 容错 | 极端状态下仍然不崩坏的设计余量。 | 大金额、小屏幕、长标题、误触 | developing |
| 语义密度 | 少量界面元素承载丰富但清晰的意义。 | 一句话意义、买到什么、同价位也许是 | developing |
| 产品重心 | 第一屏最应该被用户操作和理解的对象。 | 价值轴、焦点卡、模式控制 | developing |
| 校准 | 让用户把自己的感觉和客观尺度重新对齐。 | 金额锚点、价格带、跨界替代 | developing |
| 情绪温度 | 产品表达判断时的语气强弱。 | 不羞辱、不过度鸡汤、清醒 | developing |
| 比例尺语义 | 刻度系统同时表达数量、区间、阈值和使用判断。 | 对数尺、价格带、仪表、读数 | active |

## Distinctions

| Distinction | Why It Matters | Example |
| --- | --- | --- |
| 仪器 vs 海报 | 仪器要求可操作和可读数；海报只要求有冲击。 | 价值轴必须能拖、能反馈，而不只是竖着好看。 |
| 读数 vs 装饰 | 读数承担状态责任；装饰只承担气氛。 | `¥36,000` 必须永远可见，不能被轨道或布局遮住。 |
| 读数 vs 说明 | 好的仪器先让结构自己可读，再用文字补充。 | 价格带应进入轨道，而不只出现在段落里。 |
| 比较 vs 审判 | 比较扩展选择；审判压扁用户。 | “648 也可以是椅子”比“抽卡不理性”更有效。 |
| 轻量 vs 简陋 | 轻量是路径短、负担小；简陋是缺少必要反馈。 | 清单模式可以藏起来，但当前金额读数不能省。 |
| 具体品牌 vs 带货 | 品牌提供真实锚点；带货诱导购买。 | 原神、AirPods、MacBook 是认知锚点，不是推荐。 |

## Methods

| Method | Use When | Watch Out For |
| --- | --- | --- |
| 控制-读数分离 | 一个控件既要操作又要显示状态时 | 不要让读数跟刻度标签互相遮挡。 |
| 布局容差表 | 有长文本、大数字、小屏幕、极端状态时 | 不能只看默认 648 元。 |
| 一屏一任务 | 页面元素开始争夺注意力时 | 不要把必要上下文删到用户看不懂。 |
| 反向失败案例 | 设计看似成立但感觉不对时 | 只找缺点会忽略产品本来做对的部分。 |
| 同价位横跳 | 需要制造启发而不是分类时 | 横跳要有内在关系，不能随机猎奇。 |
| 比例尺分层 | 金额轴既要表达大小又要表达生活区间时 | 价格带、刻度、针脚不能抢当前读数。 |
