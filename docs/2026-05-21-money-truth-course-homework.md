## 0. 课程总命题

**题目：** 设计一个网页产品，帮助用户重新看见“同一笔钱可以变成什么”。

**原始洞察：** 钱在数学上是同质的。花 30 元买咖啡，和花 25 元充网盘会员，本质上都是一笔小额支出；但人的体感完全不同。更大的问题不是“贵不贵”，而是注意力经常被眼前的消费带走，让人忘记同样的钱也可以变成身体、关系、工具、能力、作品、余地。

**我的产品定义：**  
这不是记账工具，不是省钱工具，也不是消费羞辱工具。它是一个轻量的认知仪器：把一笔钱放到一把垂直的价值轴上，让用户看见这笔钱在不同生活现实中的形态。

**答辩标准：**
- 一眼看懂：用户不用读说明，也知道可以拖金额、看同价位对照。
- 不重：没有复杂账户、预算表、积分系统、教程墙。
- 有真实感：中国年轻人熟悉的品牌、价格、消费场景要进入产品。
- 有启发：跨界对照要让人停一下，而不是只做价格列表。
- 不道德化：不是告诉用户“不许买”，而是让用户先看清自己在买什么。

## 1. 第一课：问题定义

### 课堂工具：5 Whys

1. 用户为什么会后悔消费？  
   因为买完以后发现它没有留下什么。

2. 为什么当时还会买？  
   因为当下的商品更会说话：折扣、抽卡、推荐流、品牌、包装、即时情绪。

3. 为什么“真正想要的东西”没有赢？  
   因为它们通常没有出现在同一个决策画面里。椅子、体检、课程、回家的车票，不会在用户点奶茶或抽卡时自然浮现。

4. 为什么普通预算表解决不了？  
   因为预算表问的是“花了多少”，但用户真正卡住的是“这笔钱到底变成了什么”。

5. 为什么要做成可视化网页？  
   因为这类问题靠文字劝说很弱，靠“同价位物品同时出现”才会有刺痛感和清晰感。

### 作业提交

**核心问题句：**  
当我准备花这笔钱时，我能不能同时看见它可能变成的其他生活现实？

**不做什么：**
- 不做记账。
- 不做实时比价。
- 不做购物推荐返利。
- 不做大而全理财软件。
- 不把用户分成“理性/不理性”的道德等级。

**成功体验：**
用户拖到 `¥648`，看到“原神 648”时，也同时看到人体工学椅、心理咨询、近程高铁、驾照报名。那一刻不是被骂，而是意识到：原来这 648 可以通往这么不同的自己。

## 2. 第二课：用户观察

### 课堂工具：Jobs To Be Done

**用户雇用这个产品，不是为了：**
- 记一笔消费。
- 计算自己多穷。
- 得到一个标准答案。

**用户雇用这个产品，是为了：**
- 在冲动消费前，把注意力拉宽。
- 在大额消费前，判断它是不是“真的”。
- 给自己的购物清单重新排序。
- 找到一种不羞辱自己的金钱观。

### 用户画像

1. **做事的人**  
   钱最好变成工具、作品、学习曲线、稳定工作流。  
   风险：买课程、工具、软件时也可能只是买“我要开始了”的感觉。

2. **想体面出现的人**  
   钱最好变成脸、衣服、气味、状态、愿意出门的自己。  
   风险：被小红书、直播间、穿搭焦虑推着走。

3. **想要安全感的人**  
   钱最好变成体检、保险、备用金、修补未来风险。  
   风险：预防性消费不显眼，所以经常输给即时奖励。

4. **在乎关系的人**  
   钱最好变成见面、照护、共同记忆、被看见。  
   风险：用礼物代替在场，或用消费维持关系焦虑。

5. **需要安静的人**  
   钱最好变成更少噪声、更少家务、更少疼痛、更连续的注意力。  
   风险：不知道自己其实是在买“不要再被打断”。

6. **认真玩的人**  
   钱可以变成游戏、演出、旅行，但最好留下体验而不是下一次充值。  
   风险：抽卡、皮肤、订阅把玩变成概率和追赶。

### 作业提交

**用户不是缺少理财知识，而是缺少并置画面。**  
所以产品的第一原则是：不要教训用户，要把不同可能性摆到同一把尺上。

## 3. 第三课：产品定位

### 课堂工具：定位句

**For** 正在重建金钱观、容易被即时消费带走、但不想被说教的年轻人，  
**钱就是钱** 是一个轻量网页认知仪器，  
**that** 把同一笔钱可能购买的物品和服务放在一条垂直价值轴上，  
**unlike** 记账 App、预算表、购物清单或理财课，  
**it** 不问你花了多少，而问你：这笔钱最后会变成什么？

### 产品原则

1. **钱是转换器，不是分数。**  
   它可以转换成注意力、身体、关系、工具、作品、时间和未来余地。

2. **同价位并置比分类更有力。**  
   “¥648 原神”旁边出现“¥699 人体工学椅”比“游戏类消费”更有冲击。

3. **真实消费不等于正确消费。**  
   咖啡、游戏、衣服、演出都可能是真的；关键是它有没有买到用户真正要的东西。

4. **细节集中在焦点项。**  
   不让全页面变成密密麻麻的展开卡片。用户点到一个东西，再看“买到什么 / 同价位也许是 / 反思问题”。

5. **界面像仪器，不像文章。**  
   大金额轴是主控件，其他内容服务于它。

### 作业提交

**一句话产品概念：**  
把一笔钱拖到价值轴上，看它会把你带向哪里。

## 4. 第四课：信息架构

### 课堂工具：Core Interaction First

先确定唯一核心动作，再安排其它模块。

**核心动作：** 拖动竖向金额轴。  
**核心反馈：** 当前金额、焦点消费、同价位跨界替代。  
**次级动作：** 切换地区、切换模式、搜索消费、调整个人画像。

### 三个模式

1. **价值轴**  
   第一屏默认模式。只保留金额轴和焦点项。用户专心看清“这笔钱”。

2. **对照**  
   展开同价位的真实选项和注意力消费。用户需要比较时再进入。

3. **清单**  
   展开奖励画像、消费敏感度和个人奖励清单。更像轻量理财面板。

### 作业提交

**为什么不是一个页面塞满所有东西？**  
因为这个产品的力量来自“被看清”，不是来自“信息很多”。价值轴是主动作；对照和清单是用户主动要更多上下文时才打开。

## 5. 第五课：交互设计

### 课堂工具：State Machine

关键状态：
- 地区：`cn` / `us`
- 模式：`axis` / `compare` / `list`
- 金额百分比：`amountPercent`
- 选中项：`selectedId`
- 用户画像：`profileId`
- 消费敏感度：`sensitivity`
- 搜索词：`query`

### 交互约束

1. **拖动金额不能弹回默认值。**  
   如果用户拖动金额，就清空 `selectedId`，金额由百分比决定；如果用户点某个商品，金额才跟随商品。

2. **点击模式不能误触地区或敏感度。**  
   控制按钮必须限定为 `button[data-mode]`、`button[data-region]`、`button[data-sensitivity]`。

3. **当前金额读数必须永远可见。**  
   它不是刻度标签，而是独立的 `.rail-current`。

4. **大金额不能藏到轨道后面。**  
   金额主读数根据字符串长度设置 `data-size="normal|long|xl"`。

5. **视觉控制也要有语义。**  
   隐藏的 range 同步 `aria-valuetext`，让辅助技术读到和屏幕一致的金额。

### 作业提交

**交互决策：**  
竖向金额轴不是普通进度条，而是产品的主控件。它应该像一个可以拖动的价格标尺，而不是页面装饰。

## 6. 第六课：内容系统

### 课堂工具：Content Model

每个可购买项必须包含：
- `price`：近似价格锚点。
- `title`：具体消费，而不是泛泛类别。
- `brand`：能增加真实感时使用。
- `meaning`：一行意义。
- `details.buys`：这笔钱具体买到什么。
- `details.swap`：同价位可能是什么。
- `details.question`：一个反思问题。
- `lens`：`true` / `attention` / `mixed`。
- `truthScore`：真实感评分。
- `rewardTags`：用于个人画像匹配。
- `linkedIds`：特别值得并置的跨界项。

### 内容标准

**好的条目：**
- `原神 648 创世结晶`  
  因为它是中国年轻人熟悉的价格锚点，且“648”本身已经是文化符号。

- `一把入门人体工学椅`  
  因为它和 648 接近，但购买的是每天的身体状态。

- `一张近程高铁票`  
  因为它把钱变成距离缩短和关系在场。

- `一次心理咨询`  
  因为它和抽卡同价位，却买的是被认真听见的一小时。

**不好的条目：**
- “娱乐消费”
- “提升自己”
- “健康投资”
- “高性价比产品”

这些太像分类，不像生活。

### 作业提交

**内容原则：**  
每个条目都要像观察过真实生活，而不是从消费分类表里抄出来。

## 7. 第七课：视觉系统

### 课堂工具：Industrial Design Checklist

这个界面应该像：
- 金融工具的一点点冷静。
- 实验仪器的一点点清晰。
- 生活观察笔记的一点点人味。

不应该像：
- SaaS 落地页。
- 理财 App 大屏。
- 情绪鸡汤网页。
- 购物推荐导购。

### 视觉取舍

1. **大标题收一点。**  
   它要有第一眼力量，但不能压过工具本身。

2. **轨道加宽空间合同。**  
   左侧注意力消费、中央金额读数、右侧更真选项，各自有泳道。

3. **边框减轻。**  
   之前的粗边框让页面变重。新的边框更像仪器面板。

4. **阴影减弱。**  
   保留层次，但不制造“卡片堆叠”的感觉。

5. **数字单独处理。**  
   金额使用数字字体和 tabular nums，让它像读数，不像正文。

### 作业提交

**最终视觉方向：**  
克制、清楚、可检查。让用户觉得自己在调一台仪器，而不是浏览一篇劝消费文章。

## 8. 第八课：原型迭代记录

### 发现的问题

1. 大金额如 `¥36,000` 会被左侧信息栏空间挤压，视觉上像藏到轨道后面。
2. 对照模式沿用价值轴模式的宽度，右侧对照卡片被压窄。
3. 当前金额读数虽然不再和刻度重叠，但整体空间合同还不够明确。
4. 标题和焦点卡在桌面上略大，和“轻量认知仪器”的气质有冲突。

### 修正

1. 主布局改为 `minmax(820px, 1.12fr) minmax(480px, 0.88fr)`，优先保证主轴完整。
2. 金额面板改为 `minmax(260px, 0.34fr) minmax(500px, 1fr)`，给左侧读数留足空间。
3. 对照模式在宽屏下单独使用 `minmax(650px, 0.82fr) minmax(660px, 1.18fr)`。
4. 添加 `amountReadoutSize()`，长金额自动降字号。
5. 当前读数、刻度、物品 pin 的横向距离重新调整。
6. 焦点标题、阴影、边框整体减轻。

### 作业提交

**迭代结论：**  
这个产品的核心不是让轨道更漂亮，而是让每一笔钱的读数有尊严地站在它该站的位置。

## 10. 第十课：答辩陈述

如果我站在礼堂里，我会这样介绍这个作品：

> 《钱就是钱》想解决的不是“人为什么乱花钱”，而是“为什么同一笔钱在不同消费里看起来不像同一笔钱”。  
>   
> 我把它设计成一条竖向金额轴。用户拖动金额，不是在设置预算，而是在移动一个观察点。每一个价格附近，都会出现两类东西：一类容易带走注意力，一类更可能留下身体、关系、工具、作品和未来余地。  
>   
> 这个产品不裁判用户。原神 648 不一定错，咖啡不一定浅，MacBook 不一定真。它只是把它们放在同一把尺上，让用户在付款前有一秒钟看清楚：我到底想让这笔钱变成什么？
